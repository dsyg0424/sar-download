## 按优先级排序的发现（尚未修改）

### 1. 高：列表快照与实时事件存在竞态
位置：src/App.tsx:31、src/features/downloads/api.ts:59。
mergeSnapshot 只遍历 incoming；请求发出后通过事件加入的新任务，如果不在旧快照中，会从界面被移除。单任务 revision 只能保护共同 ID，不能保护快照缺失项；10 秒轮询也没有请求序号或单飞保护。
建议：给快照增加全局版本或请求水位，保留请求发出后出现的任务，结合删除墓碑；不能简单永久合并，否则真正删除的记录会复活。

### 2. 高：添加任务成功后，刷新失败会中断自动开始
位置：src/App.tsx:97–103。
add_downloads 成功后先 await refresh，再展开面板并开始任务；如果 list_downloads 短暂失败，任务已创建但不会进入自动开始逻辑，用户只看到错误，容易重复点击。
建议：以服务端返回的任务 ID 推进启动，刷新失败独立提示并重试；界面分别报告已创建、启动失败、状态同步失败。

### 3. 中：长查询无法由用户取消
位置：src/features/sar-download/store/useSarSearchStore.ts:67、148、158、188；services/sarSearchApi.ts。
busy 时更新和重置直接返回，前端没有取消接口；等待期间用户不能主动撤销当前查询后换范围。
建议：增加查询 ID、后端取消令牌和取消入口；取消后忽略旧进度，并明确保留上一轮或当前部分结果的策略。

### 4. 中：折叠下载面板仍每秒更新四次
位置：src/features/downloads/DownloadCenter.tsx、DownloadPanel.tsx:31–34、64；api.ts:59。
抽屉隐藏但组件保持挂载，250ms 定时器始终构造新状态，所有可见列表项会参与重渲染；快照对每个任务执行 find，为 O(n²)。大量任务时增加无效开销。
建议：把抽屉是否展开传入面板，关闭时暂停显示刷新；速度采样与渲染分离，Map 索引合并，列表使用虚拟滚动。

### 5. 中：GeoJSON 导出缺少独立进行中状态
位置：src/features/sar-download/components/SarResultsPanel.tsx、src/App.tsx:118。
按钮只由 adding 控制禁用，导出回调不返回 Promise，也没有 exporting 状态；连续点击可重复触发原生保存流程。
建议：异步回调贯通，导出时禁用重复操作，保留明确的取消、成功及失败状态。
